## プロジェクト JSON

AI が直接読み書きできることを狙った素直な構造。`telops` / `audioClips` / `blurs` は
Phase 2・3 用に枠だけ用意してある。

```json
{
  "version": 1,
  "output": { "width": 1920, "height": 1080, "fps": 30, "videoBitrate": 12000000 },
  "sources": [{ "id": "src_x", "name": "PXL_....mp4", "duration": 5400.0 }],
  "clips":   [{ "id": "clip_x", "sourceId": "src_x", "in": 12.5, "out": 18.2, "volume": 1 }],
  "trims":   [{ "id": "trim_x", "prevClipId": "clip_x", "nextClipId": "clip_y",
                "segments": [{ "sourceId": "src_x", "in": 18.2, "out": 21.4 }], "label": "無音" }]
}
```

`trims` は**カットで消した区間の在庫**。クリップと同じ「素材の区間」で表せるので、
映像そのものは抱えない（後述）。

`thumbnail` はサムネイル。`telops` / `images` はタイムライン側とまったく同じ形で、
`base` は元画像の**取り出し方だけ**を持つ（後述）。

### 作業フォルダ（VSCode 方式）

ブラウザにはパスの概念が無い。`File` にも `FileSystemFileHandle` にも
**親フォルダへ辿る手段が無い**ので、「プロジェクトファイルの隣にある動画」には原理的に届かない。
そこで VSCode と同じく、**フォルダごと開いてもらう**。

ツールバー左端の 📁 で `showDirectoryPicker({ mode: 'readwrite' })` を出し、
ハンドルを IndexedDB（`dirHandles` の `__work__`）に保存する。

- フォルダ直下の `*.kiriko` を探し、1 つならそのまま開く／複数なら選ばせる
- 保存はこのフォルダへ直接書く（`showSaveFilePicker` を出さない）
- 素材の名前引きは、覚えているフォルダの中でも**作業フォルダを最優先**で探す
- ライブラリのテロップを置いた時、同梱画像をこのフォルダへ実ファイルとして書き出す

**素材は作業フォルダの外にあってよい。** ドラッグ＆ドロップの時に
`getAsFileSystemHandle()` でファイルのハンドルを覚えているので、次に開いた時も
そこから読み直せる（`resolveFile` の ①）。素材を別フォルダにまとめている人の方が多い。

そのため、素材が見つからない時に出す「**素材のフォルダを選ぶ**」は
**作業フォルダ（保存先）を変えない**。覚えるのは「探しに行く場所」だけで、
求める許可も読み取りだけにしてある。作業フォルダがまだ無い時だけ、
選んだフォルダをそのまま保存先にする。

以前は選んだフォルダを無条件で作業フォルダにしていた。素材フォルダを選んだつもりが
プロジェクトの保存先まで移ってしまうので直した（2026-08-28）。

**オリジンが変わると、覚えているものは全部消える。** ファイルのハンドルも作業フォルダも
IndexedDB に入っているので、`localhost:8901` と `localhost:8903`、公開ページは
それぞれ別の記憶を持つ。動作確認用に別ポートで開くと「素材が読めない」ように見えるが、
置き場所の問題ではない。

素材ファイルそのものは JSON に入らないが、**一度開いたファイルは次から自動で読み直す**。
File System Access API のハンドルを IndexedDB に覚えておき、プロジェクトを開いた時に
名前で引いて復帰させる（ファイル選択でもドロップでも覚える）。

見つからない素材があれば上部に帯が出て、**［素材を探す］**（覚えている物の読み直し＋選択）か
**［フォルダを選ぶ］**（作業フォルダとして覚え、その中を名前で探す）で解決できる。

画像だけは、実ファイルが見つからなくても**テロップライブラリの中から同じ名前のものを探す**。
ライブラリから置いたテロップの画像は、元ファイルが手元に無いことがあるため。

> これはあくまで保険で、**ライブラリからそのセットを消すと効かなくなる**。
> ただし作業フォルダを開いていれば、ライブラリのテロップを置いた時点で
> 画像がそこへ実ファイルとしてコピーされるので、保険に頼らずに済む。

保存時の拡張子は `.kiriko`（中身は JSON）。

## テロップ（Phase 2）

Keynote → PNG 書き出しの運用を置き換えるのが目的。1 文字直すのに書き出し直す必要はない。

### テロップは「セット」

1 枚の PNG に焼いていたものを、そのまま構造として持てるようにしてある。

- **複数行**：行ごとに書体・大きさ・色・縁・横の寄せを変えられる（見出し＋日時、のような組み）
- **背景画像**：枠に敷く。帯やフレームの PNG をそのまま使える
- **アイコン画像**：文字の左右上下に添える（ロゴなど）。位置・大きさ・間隔・縦位置を指定
  - 透明な余白は自動で切り詰めるので、1920×1080 の中に小さく置かれたロゴでもそのまま使える
- セットごと移動・リサイズ・時間調整でき、書き出しにもそのまま焼き込まれる

### トラック

テロップは **T1 / T2 …** と重ねられる（A1 / A2 と同じ考え方）。
動画全体に出す見出しを T1、途中で入れるものを T2、のように分けると掴みやすい。
新しいテロップは同じ時間に重ならないトラックへ自動で入り、縦にドラッグすれば移せる。

トラックの本数は「使っている一番下＋空き 1 本」で決まる。そのため**間の行が空くと
その行を消すすべが無くなる**ので、ものを消した後に `compactTracks`（`project.js`）で
`track` を 0 から順に振り直す。並び順は変えず、同じ行にあったものは同じ行のまま残る。
呼ぶのは削除・範囲の切り取り・素材ごと外した時・プロジェクトを開いた時。
**掴んで動かしている最中には呼ばない**（空いている行へ運ぶ途中で引き戻されてしまう）。

### ライブラリ（プロジェクトをまたいで使い回す）

テロップダイアログ下部の **［★ ライブラリに保存］** で、背景画像・アイコンごと保存する。
画像を含むセットの保存時、ライブラリフォルダが未設定または許可切れなら確認を出す
（`ensureLibDir`）。`.kirikolib` の書き出しは、実ファイル参照のままの軽い形式と、
画像を埋め込む可搬な形式を選べる。
左パネルの **テロップ** タブから、別のプロジェクトでもそのまま呼び出せる。

保存先はブラウザの IndexedDB。**ライブラリフォルダ**（`dirHandles` の `__lib__`）を決めてあれば、
画像はそこへ実ファイルで置き、ライブラリには `{ name, file: true }` だけを持たせる
（IndexedDB を膨らませない・`.kirikolib` も小さくなる）。決めていない場合は
画像を dataURL で同梱するので、素材の無いプロジェクトでも
呼び出した時に自動でビンへ読み込み直す（同名の画像が既にあればそれを使う）。

一覧は**手で並べ替えられる**（掴んで上下にドラッグ）。並び順は各セットの `order` に持ち、
`sortSets` が `order` を保存日時より優先する。まだ並べ替えていないもの（`order` 無し）は
今までどおり保存日時の新しい順で、並べ替え済みのうしろに並ぶ。
新しく保存したセットは `headOrder`（最小 − 1）で先頭に入る。

**✎** で名前を変えられる（`updateSet`）。中身を直したい時は、ライブラリから置いたテロップに
出どころ（`libSetId`）を持たせてあるので、直してからもう一度 ［★ ライブラリに保存］ を押すと
**元のセットへ上書きするか聞く**。キャンセルすれば別のセットとして新しく保存する。

**ライブラリ自体はオリジンごと・ブラウザごと**に分かれる（localhost と GitHub Pages でも別）。
移したい時は テロップタブの **［書き出し］／［読み込み］** で `.kirikolib` にまとめられる
（画像も入るのでこれ 1 つで完結する）。同じ名前・同じ中身のものは重複して入らない。

- **二重縁取り**：外の白フチ（`outerStroke` × `outerScale`）＋ 内側の濃い縁（`stroke`）＋ 塗り（`fill`）＋ 影
- **塗りのグラデーション**：`fillMode: 'gradient'` で 2 色（`fill` → `fill2`）にできる。
  向きは `fillDir`（`v` 縦 / `h` 横）。掛かる範囲は**その行の 1 行ぶん**で、
  縦は文字の上端から下端、横はその行の文字が占める左端から右端。行が増えても 1 行ずつ同じ見た目になる。
  下線・取り消し線も同じ塗りを使う
- **改行対応**：テキスト欄で改行するとそのまま複数行になる
- **枠で位置と大きさを決める**：プレビュー上の枠をドラッグで移動、四隅・辺のハンドルで大きさ変更。
  枠の中での**横の寄せ**（左 / 中央 / 右）と**縦の寄せ**（上 / 中央 / 下）を指定でき、
  枠の幅で自動折り返しもする
- **吸着と画面外防止**：移動もリサイズも画面の端・中央・セーフマージンに吸着し（<kbd>Alt</kbd> で解除）、枠は画面外へ出ない。
  移動中は、同じ時刻に出ている**他の枠にも揃う**（`snapToBoxes`。同じ側の端どうし・中心どうし・
  すぐ外側に接する位置）。画面端の吸着が効いた向きはそちらを優先する
- **つまみをダブルクリック**：枠を文字の大きさにぴったり詰める
- **カーソルキー**：プレビューをクリックしてから <kbd>←</kbd><kbd>→</kbd><kbd>↑</kbd><kbd>↓</kbd> で 1px（<kbd>Shift</kbd> で 10px）移動
- **編集はポップアップ**：テロップを選ぶと編集ダイアログが開く。ヘッダをつかんで好きな位置へ動かせる
- **プリセット**：スタイルと位置をセットで保存。既定で「実況（下段中央）」「金額（右上）」「見出し」「注釈」を用意
- **タイムライン**：T1 トラックで表示時間をドラッグ／端ドラッグでトリム。
  **カットの切り替わりに吸着する**（<kbd>Alt</kbd> で解除）
- **フォント 3 ルート**
  - 内蔵 Web フォント（M PLUS Rounded / ロックンロール One / デラゴシック / 油性マジック / Kiwi Maru）
  - 「PC のフォント一覧」＝ Local Font Access API でインストール済みフォントを列挙
  - 「.ttf を追加」＝ 手持ちのフォントファイルを読み込み

プレビューと書き出しは `js/telop.js` の **同じ描画関数**を通るので、見たままが焼き込まれる。

**下線と取り消し線は canvas に無い**ので自分で矩形を引く。文字と同じ
「外フチ → 内縁 → 本体」の重ね方にするが、**フチの太さは線に合わせて縮める**
（文字と同じ太さにすると帯になって文字を潰す）。位置は文字の左端から
`inkWidth` ぶんで、寄せの補正（`alignShift`）を戻して求める。

太字・斜体・下線・取り消し線は**独立**（排他ではない）。太字＋斜体はよくある組み合わせ。

**背景画像・アイコン・文字の自由配置**は、**テロップの枠の左上からの相対**で持つ
（`bgBox` / `icon.x,y` / `textX,textY`）。文字は「文字を流し込む領域ごとずらす」形なので、
寄せ（`hAlign` / `vAlign`）や折り返し幅はそのまま効く。絶対座標にしなかったのは、枠を動かした時に画像が付いてこないと
「セット」として扱えなくなるため。左上を基準にしたのは、他の座標（`box`・画像クリップ）が
すべて左上基準で揃っていることと、枠を右下方向にリサイズしても位置がずれないため。
寄せ配置から切り替えた瞬間は、その時点で見えている位置と大きさを引き継ぐ（飛ばない）。

**フォント一覧は自前で描く**（`openFontPicker`）。`<select>` の `<option>` に
`font-family` を指定しても、macOS の Chrome はネイティブのポップアップで描くため
反映されないことがある。「どんな字か見て選ぶ」を確実にしたいので独自にした。

**一覧に載らないフォント**もある（macOS があとからダウンロードするものなど、
`queryLocalFonts()` が返さないのに CSS からは使える）。名前を直接入れる欄を用意し、
`fontAvailable()` で実際に使えるか測ってから受け付ける。
測り方は「serif と monospace という形の違う代替を指定して幅を比べ、
同じなら代替に落ちていない＝その書体が使われている」。

**日本語のフォント名**は、Local Font Access API が英語名しか返さないため、
フォントファイルの `name` テーブルから自分で読む（`js/fontname.js`）。
ファイル全部は読まない — ヘッダを 16 バイト読んでテーブル一覧の位置を求め、
`name` テーブルだけ `Blob.slice()` で切り出す（1 フォント数 MB × 数百個あるため）。
nameID 16（推奨ファミリ名）を 1 より優先し、Windows(3)/langID 0x0411 と
Mac(1)/langID 11 の両方を見る。

**字間**（`letterSpacing`）は行ごとの書式。canvas の `ctx.letterSpacing` を使う。
`measureText` は**最後の文字のうしろにも字間を足した値**を返すので、
寄せる時はその分を引く（`inkWidth` / `alignShift`）。引かないと、
中央寄せで字間の半分だけ左にずれる。測るだけの関数は `save`/`restore` で挟んで、
共有の ctx に字間を残さない。

> テロップの時刻は**出力タイムライン基準**。カットやトリムで長さが変わった分は
> [リップル](#カットに合わせて後ろを詰めるリップル)で一緒に動くが、
> クリップの**並べ替え**には追従しない。

## 字幕（SRT）

**なぜ焼き込まないか。** テロップと同じ仕組みで画面に焼き込む案もあったが、
焼き込みは 1 言語に固定されて英訳を載せられず、視聴者が消せず、
直すたびに書き出し直しになる。字幕は `.ja.srt` / `.en.srt` として書き出して
YouTube に添付する形にした。日英 2 本を添付すれば視聴者が選べるし、直すのはテキストの
差し替えだけで済む。弱点は、YouTube 以外（X / Instagram 等）に転載すると SRT は効かないこと。

**テロップとは別レイヤー。** テロップは見せ場を飾る装飾、字幕は全セリフを対象にした
2 言語・機械可読なデータで、性質が違う。無理に 1 つの仕組みに寄せると両方の要件が壊れる
ため、`js/subtitles.js` として完全に独立させた（`trims.js` と同じ、DOM も状態も触らない
純粋関数だけのモジュール）。

**1 エントリに日本語と英語を同居させる**（`{ id, start, end, ja, en }`）。
言語ごとに配列を分ける案もあったが、片方だけカットで消えた時などにズレの管理が破綻する。
同じ id・同じ時刻を 2 言語で共有する形にして、翻訳や校正を突き合わせながら進めやすくした。

**1 トラック固定・重なり禁止。** `normalizeOverlaps` で start 昇順に並べ、
前の end が次の start を超えていたら前を詰め、詰めた結果 0.3 秒未満になったものは落とす。

**分割するとテキストは前半に残り、後半は空になる**（`splitAt`）。機械的に文字数で
割ると、直すたびに手間が増えるため。SRT 書き出し（`toSrt`）では、その言語が空の
エントリは除外され、番号も振り直される。

### 目安（`LIMITS`）

| | 1 行 | 行数 | 速度 |
|---|---|---|---|
| 日本語 | 16 文字 | 2 行まで | 6 文字毎秒 |
| 英語 | 42 文字 | 2 行まで | 17 文字毎秒 |

超えるとタイムラインのブロックが赤くなり、編集フォームに何が超えているか出る
（`checkLimits`）。**字幕は逐語である必要はなく、収まらなければ短く言い直すのが正しい。**
英語は日本語より文字数を食うので、直訳すると簡単に溢れる。

### YouTube 字幕ゾーンのガイド

YouTube の字幕の大きさは視聴者の設定（50〜400%）とプレイヤーの大きさで変わるので、
制作側では確定できない。だから見た目を再現するのではなく、上の文字数の目安で守る。
ただし**出る位置は決まっている**（画面下部中央）ので、そこはガイド枠で示せる。
既定のテロップ位置（`y:820`）はこの帯と重なるため、字幕を使うならテロップを上げる
必要がある。ガイドはテロップの枠と重なると赤くなる。ON/OFF できる。

### MCP（`kiriko_get_subtitles` / `kiriko_set_subtitles`）

想定の流れ：

```
kiriko_transcribe                              → セリフを書き起こす
kiriko_set_subtitles { autoSplit: true }       → 句点・読点で自動分割し、時刻は文字数比で按分
kiriko_get_subtitles                           → 警告（長すぎ・速すぎ）の付いたものを見つける
kiriko_set_subtitles { id, en }                → id を指定して en だけ流し込み、英訳する
人間が仕上げて SRT を書き出す
```

`set_subtitles` は `mode: 'merge' | 'replace'`。`merge` では `id` があれば
**渡されたフィールドだけ**更新し、無ければ新規追加する。存在しない `id` はエラーにせず
`skipped` で報告する（AI 側の id のずれで書き込みが丸ごと失敗しないように）。
入れた後は必ず `normalizeOverlaps` 相当の整形を通す（昇順に並べ、重なりを詰め、
0.3 秒未満は落とし、全体尺に clamp）。

### 操作

<kbd>S</kbd> または ツールバーの字幕ボタンで、再生位置に字幕を追加する。
タイムラインの **ST 行**でドラッグ移動・端で伸縮（隣とは重ならない。最短 0.3 秒）。
インスペクタの「プロパティ」に日本語・English のテキスト欄、文字数と速度の警告、
開始/長さ、「再生位置で分割」「前の字幕と結合」がある。
プレビューの字幕表示は ON/OFF と `日本語 / English / 日英とも` を切り替えられる
（表示設定なので localStorage に保存。プロジェクトには入らない）。
インスペクタの「出力」タブから `.ja.srt` / `.en.srt` を保存する。

**カットに追随する。** リップル（`rippleAfter` / `insertGapAt`）でテロップ等と同じ
ように前後に詰められる。

## 音まわりとぼかし（Phase 3）

**トラック構成**：MK（マーカー）／FX（ぼかし）／IM（画像）／T1・T2…（テロップ）／
V1（映像）／A1（素材音）／A2・A3…（効果音・BGM）。

テロップと音源は **T1 / T2**、**A2 / A3** と重ねられる。BGM を流しながら効果音を 2 種類
同時に鳴らす、といった使い方ができる。新しく置いたものは同じ時間に重ならないトラックへ
自動で入り、縦にドラッグすれば移せる。空きトラックは常に 1 本下に出る。

タイムラインの高さは上端の**スプリットバー**で変えられる（記憶する）。
入りきらない時は縦にスクロールする。

- **効果音 / BGM**：mp3 をドロップするとビンに入る。ビンの行のクリック（または ＋）で再生位置に配置。
  尺 20 秒超は BGM とみなして音量 35%・フェードイン 1.5 秒／アウト 2 秒の既定値が付く
- **クロスフェード**：BGM を重ねて置き、それぞれにフェードを付ける。タイムライン上では台形で見える
- **音量**：クリップ単位／音源クリップ単位に加えて、**効果音と BGM の全体音量**（インスペクタ「音量（全体）」）。
  素材の効果音が大きすぎる時は全体音量で一括して下げられる
- **ループ**：BGM を素材より長い尺にすると、頭に戻って指定した終了位置まで繰り返す。
  書き出し（`mixInto`）もプレビュー（`AudioPreview`）も、**素材の中の位置は
  ループの長さで割った余り**で出す。足していくだけにすると素材の尺を過ぎた時点で
  「鳴らすものが無い」と見なされ、途中から鳴らそうとすると丸ごと落ちる
- **尺の調整**：タイムライン上で端をドラッグ。頭側を詰めると素材の頭出し位置も一緒にずれる
- **ぼかし**：プライバシー保護用。強さ 4〜120px。**全画面**と**部分（顔など）**を選べる
  - 全画面は、縁が透明を巻き込んで暗くならないよう、ぼかし半径ぶん拡大して描いてから切り取る
  - 部分ぼかしは楕円（矩形も可）。縁は外へ向けて薄くなるので四角い境目が出ない
  - **追従（キーフレーム）**：要所で位置を打つと間を線形補間する。動く顔に追えるようにするため
  - プレビュー上で枠をドラッグして位置と大きさを決められる（テロップ・画像と同じ操作。
    クリックで選択、四隅・辺で拡大縮小、カーソルキーで 1px、端と中央に吸着、アンドゥも効く）
  - プレビューにも実際に掛かった状態が出る（`<video>` の CSS filter では部分ぼかしを
    表現できないので、その区間だけ映像をキャンバスに描き直して重ねている）
  - テロップはぼかしの**上**に描かれるので読みやすさは保たれる

プレビューの音は Web Audio でスケジュール再生する。クリップ跨ぎのシークでは
鳴らし直さず（BGM が切れるため）、ずれが 0.25 秒を超えた時だけ組み直す。

## 書き出し（mp4）

書き出しボタンを押すと**先に保存先を聞き**、`FileSystemWritableFileStream` へ
**エンコードしながら直接書き込む**。数 GB でもメモリには載らない。
`showSaveFilePicker` が無いブラウザだけ、メモリに溜めて最後にダウンロードする。

H.264 のレベルは解像度とフレームレートから選ぶ（`pickAvcCodec`）。
4.0 固定だと 1440p 以上で `configure` が失敗するため。`isConfigSupported` で確かめてから使う。

mp4 の索引（moov）は**ファイル先頭**に置く（faststart）。末尾だと Web に置いた時の
再生開始が遅れるため。ディスクへ直接書く場合は先に場所を空ける必要があるので、
`fastStart: {expectedVideoChunks, expectedAudioChunks}` に **総尺から見積もった数 × 1.2 + 1000** を渡す。
足りないと書き出しの最後で失敗するので多めに取る。余りは `free` ボックスで埋まる。

実際の出力（12 秒・1080p30）の箱の並び:

```
ftyp:28  moov:4837  free:88827  mdat:3661495
```

## カットに合わせて後ろを詰める（リップル）

クリップの長さが変わったら、テロップ・画像・ぼかし・音源・マーカー・字幕も同じだけ動かす。
完成間近で頭を数秒切った時に、全部を手で置き直さずに済ませるため。

| 操作 | 動き |
|---|---|
| 範囲を切り取る（I→O→Delete） | `rippleAfter(a,b)`。範囲内のものは消す |
| クリップを削除 | そのクリップの占めていた区間で `rippleAfter` |
| クリップの端をドラッグ | 縮めた分は `rippleAfter`、伸ばした分は `insertGapAt` |
| クリップの並べ替え | 動かさない（どこに合わせるべきか決まらないため） |

`insertGapAt` は境目をまたいでいるものだけ終わりを伸ばして、掛かり続けるようにする。

## カットは非破壊（`js/trims.js`）

**なぜ要るか。** アンドゥは一本道なので、カットの後に別の作業をすると
「あの箇所だけ 1 秒返す」ができない。AI に下ごしらえを任せた時に
「全部受け入れるか全部捨てるか」になってしまい、それだと任せる気にならない。
**戻せることが、任せられることの前提**だった。

消した区間は捨てずに `project.trims` へ残す。クリップが `{ sourceId, in, out }` で
素材の区間を指しているだけなので、消した区間も同じ形で表せる。映像は抱えない。

**復帰の実体は隣のクリップを伸ばすこと。** 継ぎ目の手前を戻すなら `A.out += 秒`、
後ろなら `B.in -= 秒`。クリップの挿入は普通は起きない（素材の上で地続きなので）。
伸びた分は `insertGapAt` でテロップ・ぼかし・音を後ろへ送る。

| 決めごと | 理由 |
|---|---|
| 継ぎ目の位置は前後のクリップ id から毎回引き直す | 後から並びが変わっても追随する |
| 継ぎ目ごとにトリムは 1 件に保つ | 2 件あると「前を 1 秒」がどれか決まらない |
| 範囲をまたいでカットしたら、中の在庫を取り込む | またぐたびに在庫が消えては困る |
| クリップの端を伸ばした分は在庫から引く | 引かないと同じ映像が二重に戻る |
| 全部戻して繋がったらクリップを 1 本にまとめる | 切った跡が残らないように |
| 前後のクリップを見失ったら「戻せない」として残す | 黙って変な位置に置くより、分かる形で残す |

画面では、戻せる分が残っている継ぎ目に印を出す。
<kbd>&lt;</kbd> <kbd>&gt;</kbd> で継ぎ目送り、<kbd>[</kbd> <kbd>]</kbd> で 0.5 秒ずつ復帰、
<kbd>{</kbd> <kbd>}</kbd> で削り直し。範囲選択中はボタンを引っ込めて場所を譲る。

## コピー / 貼り付け

テロップ・音源・画像・ぼかしは <kbd>⌘C</kbd> / <kbd>⌘V</kbd> で複製できる。
貼り付け先は**再生位置**。長さ・書式・音量はそのままで、id だけ振り直す
（`S.clipboard` に JSON のディープコピーを持つ）。
テロップ 1 つだけの時は貼り付け後に編集ダイアログが開く（数字だけ直す使い方を想定）。

**複数まとめて**は範囲選択（<kbd>I</kbd>〜<kbd>O</kbd>）で行う。範囲がある状態で <kbd>⌘C</kbd> すると、
そこに掛かっているテロップ・音源・画像・ぼかしが全部入る。個別の複数選択は持たせていない
（選択状態を増やすと削除や移動の意味が曖昧になるため、既にある範囲選択に寄せた）。

貼り付けの基準は**いちばん早いもの**。それが再生位置に来て、残りは元と同じ間隔で並ぶ。
範囲の取り方（どこに I を置いたか）で結果が変わらないようにしている。
右クリックメニューからも同じ操作ができる。

## アンドゥ / リドゥ

プロジェクトが JSON なので、スナップショットを丸ごと積む方式（`js/history.js`）。
200 カット規模でも 1 スナップショット数十 KB なので、差分管理はしていない。最大 100 段。

- ドラッグやスライダーのような**連続する操作は 1 エントリにまとまる**。
  20 回文字を打っても、30 回スライダーを動かしても、アンドゥ 1 回で戻る
  （`commit(label, key)` の key が同じ間はまとめ、pointerup / フォーカス移動で区切る）
- 戻す・進むボタンのツールチップに「元に戻す：3.00 をカット」のように**操作名が出る**
- 素材と音源の読み込みは履歴の対象外。巻き戻しで読み込み済みメディアが消えないよう、
  スナップショット復元時に再マージしている

## 画像

「＋ 画像」または png / jpg のドロップで読み込む。ビンのサムネイル下にある
**全画面 / 画面上 / 画面中央 / 画面下 / 画面左 / 画面右** から配置する。

- 出力と同じ比率の画像（1920×1080 のテロップ用 PNG など）は、追加時に自動で**全画面**になる
- それ以外（縦長のスクリーンショットなど）は**中央**に収まる大きさで入る
- テロップと同じ枠なので、ドラッグ移動・ハンドルで拡大縮小・カーソルキーで 1px 調整ができる。
  角のハンドルは <kbd>Shift</kbd> を押しながらで比率を保つ
- **つまみをダブルクリック**：枠を画像の大きさにぴったり合わせる（`contain` の余白が消える）
- **画像をダブルクリック**：等倍（100%）に戻す。等倍で画面からはみ出す場合は収まる大きさまで縮める
- **右クリック**：削除メニューを出す（ブラウザ標準の「全て選択」等は出さない）

### 使う範囲（切り出し）

**元画像を画像編集ソフトで切り出してから読み込む、という手間を無くすためのもの。**
素材は 1 枚のまま登録しておき、置くときに `crop`（画素単位の矩形）で範囲を指定する。
同じ画像から別の範囲を何度でも取れるし、後から取り直せる。

- 描画は `drawImage` の 9 引数（素材の矩形 → 画面の矩形）
- `contain` の比率は**切り出した範囲**で決まる。正方形に切り出せば横長の枠でも正方形のまま
- 等倍（画像をダブルクリック）も、切り出した範囲の画素数を等倍とする
- はみ出した指定は画像の中に丸める（外を読んで透明が混ざらないように）
- プロパティのピッカーで、ドラッグ指定・移動・四隅で拡大縮小。使わない所は暗く落とす。
  カーソルの形（リサイズ / 手のひら / 十字）は掴む処理と同じ判定から作るので、
  見た目と挙動がずれない
- 「中身に合わせる」は既にあった透明余白の検出（`ImageLibrary.content`）を使う

メディア一覧では、画像が増えると配置ボタン 6 個で埋まるので**既定では畳む**。
名前・大きさ・サムネイルだけ出し、置くだけなら行のクリックか ＋（大きさは自動）で足りる。
置き場所を選びたい時だけ ▸ で開く。

**行のクリックで置ける**のは音源・テロップライブラリ・エフェクトと揃えたもの。
動画素材だけはクリックが「ソースモニターに読む」なので別扱いになる。

## テロップの中身をプレビューで動かす

文字・背景画像・アイコンは枠の左上からの相対で持っている（`textX/textY`、`bgBox`、`icon.x/y`）。
数値欄でしか動かせなかったので、プレビューでも掴めるようにした。

**枠ごとの移動と取り違えないよう、修飾キーで分ける。** <kbd>⌘</kbd>（Windows は <kbd>Ctrl</kbd>）
＋ドラッグ＝中身、素のドラッグ＝枠。「中身の上をドラッグしたら中身」にすると、
背景画像が枠いっぱいの時に枠を掴めなくなるため採らなかった。

- 掴む対象は小さいものから順に見る（アイコン → 文字 → 背景画像）。
  背景画像を先に見ると他を全部飲み込む
- 文字の範囲は `textOnlyBounds`（アイコンも背景画像も含めない）を使う。
  `textBounds` は**枠の当たり判定用**で、アイコンを含み、背景画像があると枠そのものを返す。
  それを掴む判定に使うと「枠を掴んだ」ことになり、少し動かすたびに枠の端へ
  吸着し直して**動かせなくなる**（補助線も出っぱなしになる）
- 文字は細いので、当たり判定を少しだけ外に広げる（24px）。ただし枠いっぱいには広げない。
  最初は「どれにも当たらなければ文字」にしていたが、背景色だけの所を掴んでも
  文字が動いて驚くのでやめた
- 「自由に決める」が入っていなければ、**今見えている位置のまま**入れてから掴む。
  そうしないと掴んだ瞬間に飛んで、狙って動かせない
- 動かしている間は**枠の**端と中央に吸着する（`snapInside`。<kbd>Alt</kbd> で解除）。
  枠の外へ出したい場合もあるので、吸着だけで押し込めはしない

## 全画面ぼかしは画角を変えない

ぼかしは画像の外側まで滲むので、そのまま掛けると縁が透けて暗く落ちる。
以前はそれを隠すために**映像を 1 割ほど拡大**していたが、ぼかしが切れる瞬間に
画角が戻って「びくっ」と動いて見えた（書き出しにも同じ動きが入っていた）。

いまは余白付きのキャンバスに「引き伸ばした絵（余白埋め）＋本来の絵」を描き、
**余白ごとぼかしてから中央だけを出す**。滲むのは余白の縁＝画面の外なので、
拡大しなくても縁が落ちない。

先に切り出してからぼかすと切り口が滲んで縁が透ける（実測で端の不透明度が 130 になった）。
**ぼかす前に余白を用意すること。**

プレビューも同じ `drawBlurred` を通す。CSS filter は、キャンバスが間に合わなかった時の
保険として残してある（拡大はしない）。

## プレビューで選択を解く

プレビューの**何も無い所を押すと、枠とハンドルが消える**。
仕上がりを確かめたいだけなのに、枠を外すすべが無かった。

外れるのは**プレビュー上に枠が出ているもの**（テロップ・画像・部分ぼかし）だけで、
タイムライン側の選択（クリップ・音源・マーカー）は残す。
枠だけ外したいのに、選んでいたクリップまで失うと困るため。
テロップダイアログは選択が無くなると自動で閉じる。

## 画面外防止は、ぼかしには掛けない

テロップや画像は画面外に出すと見失うので中に留める（`clampBox`）。
**ぼかしだけは例外。** 人が画面の外へ歩いて消えていく時、枠も外へ送れないと
最後まで追えないため。吸着（<kbd>Alt</kbd> で解除）はそのまま効く。

## タイムラインの見た目

- **サムネイル**：V1 にフィルムストリップを出す。1.5 時間ぶんを先に作るのは無理なので、
  **画面に見えている範囲だけ**を 1 枚ずつ遅延生成してキャッシュする（表示範囲が変わったら
  未処理の要求は捨てる）。実測 1 枚 40ms 程度
- **波形**：A1 は素材の音声を 20 秒区間ごとに遅延デコードしてピークを貯める（50ms 刻み）。
  A2 の SE / BGM は AudioBuffer から即時に作る。無音区間が見えるのでカット位置を探しやすい
  - 素材ごとに**最大値で正規化**する。小さい音で録れていると等倍では平らに見えてしまうため
- どちらもタイムライン右上の **▣**（サムネイル）／**〜**（波形）で切り替えられる
- 見出し（MK / FX / IM / T1 / V1 / A1 …）は 2 文字なので、`TRACK_TIPS` の説明を `title` で出す
- プレビューのシークバーで飛んだ時は、表示範囲から外れていれば**拡大率を変えずに**寄せる
  （`revealPlayhead`）

## マーカー（メモ）

タイムライン最上段の **MK** トラック。<kbd>M</kbd> で再生位置に立てる。

- **点マーカー**：位置とメモだけ。<kbd>,</kbd> <kbd>.</kbd> で前後のマーカーへ飛べる
- **区間マーカー**：長さを付けると区間になる。左右どちらの端もドラッグで詰められる
  - 種別は **残す**（緑）／**消す**（赤）／**メモ**（黄）。
    「セリフの所に残す」でも「無音の所に消す」でも、同じ流れで処理できる
- **［区間外］**（<kbd>G</kbd> 次へ／<kbd>F</kbd> 前へ）：区間マーカーの**外側**（＝消す候補）を 1 つずつ範囲選択して、そこへ移動する

一番手間の掛かる「自分が喋っている所だけ残す」作業を狙った機能。
AI に「セリフが取れる箇所に、セリフをメモとして区間マーカーを立てて」と頼んでおき、

1. <kbd>G</kbd> で次の「区間外」へ飛ぶ（<kbd>F</kbd> で前に戻れる）
2. 中身を見て、必要なら範囲の端を詰める
3. <kbd>Delete</kbd> で切り取る

を繰り返す。**AI の区間が正確とは限らない**ので、まとめて消すより取りこぼしに気付ける。
（一括で消したい時は、マーカーを右クリック →「区間マーカーの外を全部切り取る…」）

マーカーの位置（区間なら両端）はドラッグの**吸着先**にもなる。
**再生位置のドラッグ**もカットの境目・マーカー・範囲の端に吸着する（<kbd>Alt</kbd> で解除）。
画像やテロップをカットの頭にぴったり合わせたい時に効く。
置いてあるもの（テロップ・画像・音源・ぼかし）の**先頭**にも吸着する（`elementStarts`）。
これは再生位置のドラッグ専用で、ものを動かす時の吸着先には入れない。
入れると自分自身の先頭に吸い付いて動かせなくなるため。

## ツールチップ

ブラウザ標準の `title` は出るまでが 1〜2 秒あり、**その時間は変えられない**。
0.5 秒で出したいので、`title` を `data-tip` へ退避して自前で出している
（読み上げ用に `aria-label` は残す）。遅延は `js/main.js` の `TIP_DELAY`。

タイムライン左端の見出し（MK / FX / IM / T1 / V1 / A1 …）は 2 文字で意味が分からないので、
`TRACK_TIPS` に説明を持たせて `title` に流している。

## サムネイル

YouTube 用の 1 枚絵。動画編集ではないが、やることは
「元画像を敷いて、テロップを載せる」だけで、**Kiriko に既にある機能そのもの**だった。
だから新しく作ったのは合成と書き出しだけで、テロップ・画像・枠の操作は全部使い回している。

**置き場所はモニターの第 3 タブ**（ソース / プログラム / **サムネ**）。
インスペクタのタブや出力タブの中ではない。サムネ作りの本体は
「テロップをドラッグして位置を決める」作業で、それには大きい絵が要るため。
インスペクタは選択中のテロップの設定に、そのまま使える。

**座標系は出力解像度のまま。** 1280×720 で編集せず、`output.width/height`
（既定 1920×1080）で持って、**書き出す時だけ縮める**。こうすると：

- `drawTelop` / `drawImageClip` / `boxes.js` が一切の分岐なしでそのまま動く
- タイムラインのテロップを ⌘C → サムネで ⌘V したとき、位置がずれない
- 文字の縁が痩せない（小さいキャンバスに直接描くと縁が潰れる）

解像度を変えた時の作り直し（`rescale`）も、タイムラインと同じ処理を通す。

**元画像は「どこから取るか」だけを持つ。**

| `base` | 中身 |
|---|---|
| `{ kind: 'frame', time }` | 出力タイムラインのその時刻の**素のフレーム**（テロップもぼかしも乗せない） |
| `{ kind: 'asset', assetId }` | `imageAssets` の画像。読み込みも保存も既存の素材と同じ経路 |

絵そのものをプロジェクトに入れると `.kiriko` が数百 KB 単位で膨らむので、
実体は `S.thumbBase`（`ImageBitmap`）に抱えるだけにして、`baseKey` が変わった時だけ作り直す。
比率が違う元画像は、余白を作らず中央で切り取って画面いっぱいに敷く（`drawCover`）。
サムネらしい絵になるのはこちらだった。

**置き場所を差し替えるだけにする。** サムネモードでは `telopList()` / `imageList()` が
`project.thumbnail` 側を返す。これだけで選択・編集・削除・コピー・⌘Z・
テロップダイアログがそのまま効く。タイムラインの描画は `project.telops` を直接見ているので、
**サムネのテロップはタイムラインにも動画にも出ない**。

モードを跨ぐ時は選択を落とす。落とさないと、見えないものが選択状態のまま残る。
時刻を持たない都合上、テロップ・画像の設定から開始／終了の欄はサムネでは出さない。

**シリーズ物の使い回しは、他の `.kiriko` を丸ごと読ませる形にした。** 毎回同じ文字組みを
作り直すことになるので、前に作った `.kiriko` からサムネの文字と画像を持ってこられるように
した。ライブラリに登録する形にしなかったのは、使い回したい単位が「テロップ 1 個の書式」
ではなく「サムネ 1 セット丸ごと」で、しかも正解データが前回の `.kiriko` にそのまま残って
いるため。新しい保存先を作らずに済む。

**解像度の読み替えが要る。** 座標系が出力解像度そのままなので（前述の通り）、4K の
プロジェクトから 1080p へ持ってくるとちょうど 2 倍になる。実際にこれをやらかした。
取り込み元と現在の `output` の比で、box・bgBox・textX/Y・rowGap・アイコン・各行の
size / strokeWidth / letterSpacing を全部かけ直す。

**画像素材は名前で繋ぎ直す。** `.kiriko` には id・名前・幅高さしか無く実体は別
（IndexedDB）なので、同じ名前の素材があればその id に差し替え、無ければ空の素材として
登録して「素材の再リンク」に出す。macOS のファイル名は NFD で入ることがあり、見た目が
同じでも比較が false になるので、比べる前に NFC へ正規化する。

**重ね順は取り込み元のまま**にする。文字を先に積むと背景の画像が上に乗って全部隠れる
（これも一度やった）。

**元画像（`base`）は取り込まない**。回ごとに違うものなので。

## 重ね順（Z オーダー）

画像とテロップは同じ重ね順の列に並ぶ。インスペクタ／テロップダイアログの
**［最前面へ］［最背面へ］** で入れ替える。

内部的には各要素が `z` という数値を持っていて、描画時に昇順で重ねるだけ。
「最前面へ」は最大値 +1、「最背面へ」は最小値 -1 を振るので、値がぶつからない。
旧いプロジェクトは画像 → テロップの順（従来の見た目）で `z` を補完する。

## ボタンの置き場所

**操作の対象で置き場所を決める**。同じ操作のボタンを何箇所にも置かない。

| 場所 | 対象 | 中身 |
|---|---|---|
| ツールバー | アプリ全体 | 作業フォルダ / 開く / 保存 / 戻す / 進む / ヘルプ / 書き出し |
| ソースモニター下 | ソース | IN・OUT 表示 ＋ クリップ追加 |
| タイムライン上部 | タイムライン | テロップ追加 ／ 範囲（開始 / 終了 / 切り取り / コピー / 貼り付け / 解除）／ 削除 ／ 表示切替 ／ 拡大縮小 |
| 左パネル | 追加するもの | メディア（素材を追加＋絞り込み）、エフェクト（ぼかし）、テロップ（ライブラリ） |

範囲まわりのボタンは**使える時だけ出す**。通常は［開始］だけを置いておき、
開始を打つと［終了］［解除］と範囲の表示が、範囲になると［切り取り］［コピー］が、
コピーすると［貼り付け］が出る。終了から打つことはまず無いので、
最初から並べていると迷うだけだった。

ボタンはアイコン＋ツールチップ。**書き出し**（主要動作）と**切り取り**（不可逆）だけは
誤操作を避けるためラベルを併記している。アイコンは外部依存を避けてインライン SVG
（`index.html` 冒頭の `<symbol>` 群）。ツールチップにはショートカットも入れてある。

## パネルの構成

**左（ビン）**

- **メディア**：**［素材を追加］1 つ**で読み込む（動画 / 音源 / 画像は拡張子で振り分ける）。
  その下の **すべて / 動画 / 音源 / 画像** は絞り込み。各行の **×** でプロジェクトから外せる
  （使っている場合は何がいくつ消えるかを確認する。⌘Z で戻せる）
- **エフェクト**：今はぼかしのみ。`js/main.js` の `EFFECTS` に足せば一覧に並ぶ
- **テロップ**：セットのライブラリ。ライブラリフォルダもここで決める

**まん中（モニター）**

- **ソース**：読み込んだ素材そのもの。IN / OUT を打つ場所
- **プログラム**：編集後の仕上がり
- **サムネ**：YouTube 用のサムネイル（後述）

**右（インスペクタ）**

- **プロパティ**：選択中の要素（クリップ／ぼかし／音源／画像）。何かを選ぶと自動でこのタブに切り替わる
- **出力**：解像度（4K / WQHD / FHD / HD）・フレームレート・ビットレート・全体音量

解像度を変えると、置いてあるもの（テロップ・画像・ぼかし・保存済みプリセット）の
**位置と大きさを新しい出力に合わせ直す**（`project.js` の `rescale`）。
座標は出力の画素で持っているので、直さないと FHD → 4K で画面の左上に寄ってしまう。
横は `sx`・縦は `sy` で伸ばし、文字の大きさや縁の太さのような向きを持たない量は
**小さい方**に合わせる（16:9 → 9:16 のように比が変わる時に溢れさせないため）。
画像の `crop` は素材側の画素なので触らない。履歴に積むのでアンドゥで戻せる。

`telop.js` の既定プリセットと既定の枠は 1920×1080 基準で書いてあるので、
使う時に出力の大きさへ直す（`toOutputScale`）。プロジェクトに保存済みのプリセットは、
その時の出力の大きさで入っているのでそのまま使う。
- **メモ**：作業メモ

テロップだけはフローティングダイアログ側で編集する（プレビューのすぐそばで打てるように）。
ショートカット一覧はツールバーの **?**（または <kbd>?</kbd> キー）で開く。

## プロジェクトの保存先

`.kiriko` を開いたら、**ファイル名とハンドルを `S.projectFile` に覚える**。
保存はこの順に試す。

1. 開いたファイルのハンドルへ書き戻す（同じファイルが更新される）
2. 作業フォルダに、同じ名前で書く
3. `showSaveFilePicker` で聞く（選ばれた名前を以後の保存先にする）

タイトル（`project.title`）は中身の見出しであってファイル名ではないので、
**保存名は開いたファイル名を優先する**。タイトルが未設定のときだけファイル名から補う。

> 以前はタイトルだけを見て `${title}.kiriko` に保存していたため、
> 開いたプロジェクトを編集して保存すると `無題プロジェクト.kiriko` という別ファイルになっていた。

### タイトルの既定値・上書き確認・名前を付けて保存（2026-08-29）

`無題プロジェクト` は元々「まだ名前が決まっていない印」として扱われていた
（開いたファイル名の方が分かれば、`isUntitled()` でそちらに差し替える）。
その作法を広げて、以下の 3 点を直した。新しい概念は増やしていない。

**タイトルの既定値に作業フォルダ名を使う**

作業フォルダを開いて新規に始めると、`isUntitled()` の間は
`defaultProjectTitle()`（`S.workDir?.name` があればそれ、無ければ従来通り
`無題プロジェクト`）が既定になる。フォルダを開いた直後（中に既存プロジェクトが
無い時）と、`saveProject()` の冒頭の両方でこれを効かせている。
**あえて初回に名前を聞かない**のは、「保存で止まらない」方針を壊さないため
（作業フォルダを選ぶだけで編集を始められる、というのがこのアプリの前提）。
名前を尋ねるダイアログを挟むと、そこだけ操作が割り込みになってしまう。
なお既存プロジェクトを開いた時はそちらの名前が正しいので、この既定は
**絶対に上書きしない**（`useWorkFolder()` はプロジェクトが 0 件の時だけ触る）。

**経路②（作業フォルダへの直接保存）での上書き確認**

`saveProject()` は作業フォルダに書ける時、毎回選ばずにそのまま保存する。
これは書きやすさのためだが、同じフォルダで新規プロジェクトを 2 つ始めると
黙って上書きされてしまう。**今開いているファイル以外**に同名がある時だけ
`confirm()` で尋ね、キャンセルなら `nextFreeName()`（`filestore.js`）で
空いている連番（`-2`, `-3`, …）を探して保存する。開いているファイルへの
上書き保存は今まで通り黙って通す（毎回聞かれては使い物にならない）。

**名前を付けて保存**

`⇧⌘S` / `Ctrl+Shift+S`（ツールバーの保存の隣のボタン）で、常に新しい名前を
尋ねてから保存し、以後の保存先をそちらへ切り替える。`showSaveFilePicker` が
使える環境ではそれを、無ければ `prompt()` で名前を聞いて作業フォルダへ書く。
保存後は `S.project.title` もファイル名から付け直す。

## Kdenlive の取り込み

`.kdenlive` は「開く」からでもドロップでも取り込める（既存プロジェクトのカット列を引き継ぐ）。
Kdenlive の作りに合わせて、以下を面倒みている。

- 1 トラックが内部に持つ 2 本の playlist を両方読む（片方だけだと取りこぼす）
- **映像トラックが複数ある場合は位置順に統合する**。実素材では V1 の隙間を V2 の
  クリップが埋めている作りで、V1 だけ読むと 12 クリップ落ちた
- `<blank>`（隙間）から各クリップのタイムライン位置を求めて並べ直す
- MLT の `out` は最終フレームなので、長さは `out - in + 1 フレーム`
- 重ねて置かれたクリップ（PinP 等）は Kiriko の 1 本の V1 では表せないので取り込まず、
  件数を知らせる

## MCP 連携（設計）

```
MCP クライアント ──stdio── mcp/server.js ──WebSocket(127.0.0.1:8910)── ブラウザの Kiriko
```

繋ぎ方と提供ツールの一覧は [`../mcp/README.md`](../mcp/README.md)、
ページ内 JS から直接叩く場合は [AUTOMATION.md](AUTOMATION.md)。ここは設計の記録だけ。

**方針**

- **動画そのものは外に出ない**。やり取りするのは編集内容の JSON と、
  明示的に要求された時のフレーム画像だけ。待ち受けは `127.0.0.1` のみ
- 書き込み系は Kiriko の履歴に積むので、**人間が <kbd>⌘Z</kbd> で戻せる**
- AI は下ごしらえまで。範囲の詰めと最終判断は人間が画面を見て行う
- `bme.call(cmd, args)` と MCP は**同じコマンド実装**を通る（`runCommand`）。
  経路で挙動がずれないようにするため
- **カットは非破壊**なので、AI は迷ったら少し多めに切って
  「気になる所は戻してください」と言える（判断を渋って中途半端に切るより実用的）

**長い処理の最中も人間は編集を続けられる**

書き起こしは実時間の 1〜1.5 倍かかる。その間に人間はカットを進めるので、
結果が返ってきた瞬間に手元を乱さないようにしてある。

| 危なかったこと | 対処 |
|---|---|
| 開始時点のタイムライン時刻でマーカーを立てると、途中の編集でずれる | 結果は**素材の時刻**で返し、変換は立てる直前に行う |
| 素材のその範囲が既に切られていた | 変な位置に置かず落とし、`dropped` で件数を返す |
| ドラッグの途中で履歴のスナップショットが撮られる | 書き込みは `bme.busy()` が false になるまで待つ（15 秒で諦める） |
| カットで尺が変わると、人間が見ていた場所がずれる | 再生位置を `rippleTime` / `insertTime` で追随させ、同じ映像を指したままにする |
| AI の書き込みで選択や拡大率が飛ぶ | 選択はクリップが残っていれば保つ。`set_project` でも拡大率を変えない |

**GitHub Pages（https）に置いたものからでも繋がる** — localhost は安全なオリジンとして
扱われるため（Safari だけは塞いでいる）。この点は実機の Chrome で TCP レベルまで確認済み。

**想定する流れ**

```
「無音の所を調べて、消す候補としてマーカーを立てて」
  → kiriko_find_silence → kiriko_add_markers(kind: 'cut')
  → 人間が G / F で 1 つずつ確認して Delete
```

「セリフの所に keep」でも「無音の所に cut」でも、Kiriko 側は同じ流れで処理できる。

**本命の流れ**（書き起こしから）

```
kiriko_transcribe { addMarkers: true, pad: 3 }   → セリフに「残す」区間マーカー
kiriko_cut_outside_markers { pad: 3, dryRun: true }  → まず見積もりを出す
kiriko_cut_outside_markers { pad: 3, minGapSec: 5 }  → 実行
[ ] キー / ボタン                                → 切りすぎた所を戻す
```

`pad`（のりしろ）が要る。whisper のマーカーはセリフにぴったり張り付くので、
0 のままだと語頭・語尾が欠ける。`dryRun` は「95 分の素材から 79 分消します」を
実行前に人間へ見せるためのもの。

セリフの書き起こしは `whisper.cpp` をローカルで回す（音声はマシンから出ない）。
**無音には whisper をかけない** — 何も言っていない所に文章を作ってしまうため、
Kiriko の音量データで「音がある区間」だけを切り出して渡している。

### 走行中の素材で分かったこと（2026-08-28 / 配達動画 95 分で照合）

自転車で走っている間はロードノイズと風が途切れないので、**無音として切り出せない**。
そこに whisper を掛けると問題が 2 つ出る。

**1. 繰り返しループ。** 長い区間をそのまま渡すと、直前の文脈を引きずって
同じ文を延々と吐き続ける（10 分の音声で 39 分かかり、中身は同じ 1 文の繰り返しだった）。
`-mc 0` で文脈を持ち越さないようにして回避する。
**区間ごとに whisper を呼び直す今の作りは、これに対しても正しい。**

**2. 幻聴。** 何も言っていない所にそれらしい日本語を作る。実素材と照合したところ、
はっきりした特徴が 3 つあり、どれも「人間が残した割合 0%」だった。

| 特徴 | 中身の例 |
|---|---|
| ちょうど 30 秒（whisper の窓いっぱい） | その窓で発話が見つからなかった印 |
| 学習データ由来の決まり文句 | 「ご視聴ありがとうございました」「おやすみなさい」 |
| 同じ語の繰り返し | 「東京都交通地は、東京都交通地を通過します」 |

落とすと下ごしらえの精度が大きく変わる。30 分ぶん（10〜20 分・45〜55 分・80〜90 分）を
実際の編集結果と照合した数字。

| | 肩代わり | 正しさ |
|---|---|---|
| 幻聴を落とさない | 17.5% | 100% |
| **落とす** | **68.2%** | **99.4%** |

のりしろ（`pad`）の効き。0 だと語頭・語尾が欠ける。**3 秒が釣り合うところ。**

| のりしろ | 切る量 | 正しさ | 誤って消す | 肩代わり |
|---|---|---|---|---|
| 0 秒 | 20.9 分 | 97.1% | 36 秒 | 79.0% |
| **3 秒** | **17.7 分** | **99.4%** | **6 秒** | **68.2%** |
| 5 秒 | 15.7 分 | 100% | 0 秒 | 60.8% |

区間ごとの肩代わりは 68.1% / 56.5% / 78.8%。内容が濃い区間ほど自動化の余地は小さい。
95 分を 16 分に削る 1 時間の作業なら、**20〜25 分程度まで減る**見込み。

**前処理はしないこと。** ノイズ除去（highpass + afftdn）は whisper にも
Silero VAD にも逆効果だった。whisper は後半が丸ごと欠け、VAD は 95 分中 92.7 分を
発話と誤判定した。素の音声を渡す。

## テスト

ビルドが無いぶん、壊れても実行するまで気付けない。3 層に分けて置いている。

| 層 | 場所 | 何を見るか | 時間 |
|---|---|---|---|
| 単体 | `test/unit/` | 計算とデータ構造（`edit` / `project` / `boxes` / `history` / `images` / `waveform` / `telop` / `exporter` / `thumbnail` / `subtitles` / `commands`） | 1〜2 秒 |
| 静的検査 | `test/static/` | 重複 id、`$('x')` の実在、未使用 id、SVG の参照先、リンク切れ、CSS 変数の未定義 | 1 秒未満 |
| 結合 | `test/e2e/` | 実 Chrome で読み込み→カット→テロップ→**実書き出し**まで。レイアウトの実測も | 1 分ほど |

```bash
npm test          # 単体＋静的検査。依存なしで走る（node --test だけ）
npm run test:e2e  # 結合。puppeteer-core ＋ システムの Chrome ＋ ffmpeg
npm run hooks:install   # push 前に npm test を通す git フックを入れる
```

**素材はその場で作る。** `test/.fixtures/` に ffmpeg で短い mp4 / mp3 / png を生成する
（`testdata/` は git 管理外なので、それに依存させない）。

**入口は `window.bme`。** 結合テストは MCP と同じコマンド経路を通るので、
テストのために別口を用意していない。作業フォルダのゲート解除も、
`showDirectoryPicker` だけ差し替えて実際の［作業フォルダを開く］を押している。

**DOMParser や Canvas が要るもの**（`kdenlive` / `telop` の描画系）は node では動かないので、
`test/e2e/modules.test.mjs` でブラウザの中から `import()` して検証する。

### この 3 層で捕まえた実際の退行

| 事例 | 捕まえる層 |
|---|---|
| `id="overlay"` の重複で書き出しダイアログが出ない | 静的 |
| 素材バーが消えるとタイムラインが 6px に潰れる | 結合（高さの実測） |
| `min-height:0` 忘れでダイアログのボタンが枠外へ | 結合（位置の実測） |
| H.264 レベル 4.0 固定で 1440p 以上が失敗 | 単体（`avcCodecCandidates`） |
| 並べ替えが同じ位置で振動する | 単体（`dropIndex` の総当たり） |
| Kdenlive の複数トラックを取りこぼす | ブラウザ内モジュール |
| 使わなくなった SVG シンボルが残る | 静的（未使用 id） |
