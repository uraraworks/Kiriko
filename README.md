# Browser Movie Editor

ブラウザだけで完結する動画編集ツール（自分用）。
企画書: `_claude_work/hisho-san/docs/ブラウザ動画編集ツール/企画書_20260827.md`

## 現状：Phase 0 〜 3

- **Phase 0**：実素材の読み込み → シーク再生 → in/out でカット → 連結して mp4 書き出し
- **Phase 2**：テロップのテキスト直接編集（二重縁取り・フォント・サイズ・位置・プリセット）
- **Phase 3**：効果音 / BGM の配置、音量・フェード（クロスフェード）、区間ぼかし

企画書で挙がっていた実使用機能 6 つ（カット・テロップ・SE・BGM・ぼかし・音量）は
ひととおり通っている。

- **処理は 100% クライアント完結**。動画はアップロードせず、ローカルファイルを直接読む
- 14GB の素材でもメモリに載せない（moov だけ解析し、実データは `File.slice()` で都度読む）
- 書き出しは「デコード → Canvas 合成 → エンコード」の流水処理

## 検証結果（2026-08-27 / M2 Mac・Chromium系）

実素材 `PXL_20251001_021741207.ACTIVE.TS.mp4`（HEVC 1080p / 14GB）の先頭 90 秒を切り出して検証。

| 項目 | 結果 |
|---|---|
| moov 解析 | 2 回のリード（mdat 14GB を読み飛ばし）／17ms |
| デコード | `hvc1.1.6.L123` OK、AAC は esds から ASC 抽出で OK |
| 書き出し | 12 クリップ・60 秒を **9.2 秒（実時間比 6.5 倍）** |
| 出力 | H.264 avc1 1920×1080 / AAC 48kHz ステレオ |
| CFR 精度 | 1800 フレーム丁度・フレーム間隔 33.33ms が全継ぎ目で乱れなし |
| 映像内容 | in 点のフレームが元素材と一致 |
| 音声 | max_volume が元素材と一致（-5.9 dB） |
| テロップ焼き込み | 二重縁取り・改行・Web フォントとも出力に反映。in/out はフレーム単位で正確 |
| ぼかし | 指定区間だけ掛かり、フチが暗くならない。テロップは上に乗って鮮明 |
| 音声ミックス | 和太鼓 SE が置いた位置（0.7 秒）に RMS 0.294（期待値 0.311）で出現。BGM は全域で加算され、フェードインも反映 |

15 分の完成尺なら書き出しはおよそ 2〜3 分の見込み。

※ 音声は AAC エンコーダのプライミング分だけ映像より 70ms ほど長く出る（頭は揃っている）。

## 使い方

```bash
python3 -m http.server 8901
```

`http://localhost:8901/` を Chrome / Edge で開く（`file://` だと WebCodecs 系 API が見えない）。

1. **素材を開く**（または mp4 をドロップ）
2. ソースモニターで <kbd>I</kbd> / <kbd>O</kbd> を打って <kbd>Enter</kbd> でクリップ追加
3. タイムラインで並べ替え・トリム
4. <kbd>T</kbd> でテロップを追加し、プレビュー上でドラッグして位置決め
5. <kbd>B</kbd> でぼかし区間、「＋ 音源」で mp3 を読み込んでビンの ＋ から配置
6. **書き出し** で mp4 保存

`.kdenlive` を開くと既存プロジェクトのカット列（in/out）を取り込む。
該当する mp4 を読み込むと自動でクリップに反映される。

## プロジェクト JSON

AI が直接読み書きできることを狙った素直な構造。`telops` / `audioClips` / `blurs` は
Phase 2・3 用に枠だけ用意してある。

```json
{
  "version": 1,
  "output": { "width": 1920, "height": 1080, "fps": 30, "videoBitrate": 12000000 },
  "sources": [{ "id": "src_x", "name": "PXL_....mp4", "duration": 5400.0 }],
  "clips":   [{ "id": "clip_x", "sourceId": "src_x", "in": 12.5, "out": 18.2, "volume": 1 }]
}
```

素材ファイルそのものはブラウザ側に保持できないため、プロジェクトを読み込んだ後に
同名の mp4 を開くと自動で再接続される。

## テロップ（Phase 2）

Keynote → PNG 書き出しの運用を置き換えるのが目的。1 文字直すのに書き出し直す必要はない。

- **二重縁取り**：外の白フチ（`outerStroke` × `outerScale`）＋ 内側の濃い縁（`stroke`）＋ 塗り（`fill`）＋ 影
- **改行対応**：テキスト欄で改行するとそのまま複数行になる
- **位置**：プレビュー上をドラッグ。画面中央・左右端・上下にスナップする（<kbd>Alt</kbd> でスナップ解除）
- **プリセット**：スタイルと位置をセットで保存。既定で「実況（下段中央）」「金額（右上）」「見出し」「注釈」を用意
- **タイムライン**：T1 トラックで表示時間をドラッグ／端ドラッグでトリム
- **フォント 3 ルート**
  - 内蔵 Web フォント（M PLUS Rounded / ロックンロール One / デラゴシック / 油性マジック / Kiwi Maru）
  - 「PC のフォント一覧」＝ Local Font Access API でインストール済みフォントを列挙
  - 「.ttf を追加」＝ 手持ちのフォントファイルを読み込み

プレビューと書き出しは `js/telop.js` の **同じ描画関数**を通るので、見たままが焼き込まれる。

> テロップの時刻は**出力タイムライン基準**。クリップを並べ替え／トリムしてもテロップは追従しないので、
> カットを固めてからテロップを載せる運用が前提。

## 音まわりとぼかし（Phase 3）

**トラック構成**：FX（ぼかし）／T1（テロップ）／V1（映像）／A1（素材音）／A2（効果音・BGM）。
A2 は上段が効果音、下段が BGM の 2 段になっていて重ならない。

- **効果音 / BGM**：mp3 をドロップするとビンに入る。ビンの ＋ で再生位置に配置。
  尺 20 秒超は BGM とみなして音量 35%・フェードイン 1.5 秒／アウト 2 秒の既定値が付く
- **クロスフェード**：BGM を重ねて置き、それぞれにフェードを付ける。タイムライン上では台形で見える
- **音量**：クリップ単位（インスペクタ）＋ 音源クリップ単位。素材に音声トラックが無くても SE/BGM は載る
- **ぼかし**：区間指定の全画面ぼかし（プライバシー保護）。強さ 4〜120px
  - 縁が透明を巻き込んで暗くならないよう、ぼかし半径ぶん拡大して描いてから切り取っている
  - テロップはぼかしの**上**に描かれるので読みやすさは保たれる

プレビューの音は Web Audio でスケジュール再生する。クリップ跨ぎのシークでは
鳴らし直さず（BGM が切れるため）、ずれが 0.25 秒を超えた時だけ組み直す。

## AI 連携フック

`window.bme` からプロジェクトを直接読み書きできる。Phase 4 の MCP 連携はここに繋ぐ。

```js
bme.exportProjectJSON()      // 現在の編集内容を JSON 文字列で取得
bme.loadProjectJSON(text)    // JSON を流し込んで UI に反映
bme.project.clips            // カット列を直接いじる → bme.render()
bme.project.telops           // テロップ列（テキスト・時刻・スタイル）
bme.project.blurs            // ぼかし区間
bme.project.audioClips       // SE / BGM の配置
bme.telop.createTelop(t0,t1,style,text)
```
